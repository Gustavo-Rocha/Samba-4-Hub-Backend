# Introduction

Esta especificação define formalmente o modelo de persistência relacional do **Samba4Hub (MVP Fase 1)** em PostgreSQL utilizando Entity Framework Core 10 (.NET 10 / C# 14), a orquestração via .NET Aspire 13.5.4, a validação de dados na borda da aplicação via FluentValidation e a rotina segura de bootstrap de migrações em ambiente de desenvolvimento local.

---

## 1. Purpose & Scope

- **Propósito**: Estabelecer os contratos de dados, regras relacionais, mapeamentos Fluent API, convenções de integridade, identificação fiscal (CPF/CNPJ) e ciclo de vida de migrações para o MVP do Samba4Hub.
- **Escopo**:
  - Camada de Domínio (`src/Samba4Hub.Domain`): Entidades de negócio, enums fortemente tipados e o Value Object `DocumentoFiscal`.
  - Camada de Dados (`src/Samba4Hub.Data`): `Samba4HubDbContext`, classes `IEntityTypeConfiguration<T>`, interceptor de auditoria UTC, fábrica de design-time, seed da taxonomia de instrumentos e extensão de automação de migração (`MigrationExtensions`).
  - Camada de Injeção de Dependência (`src/Samba4Hub.IoC`): Registro centralizado de persistência no host Aspire via extensão `AddSamba4HubData`.
  - Camada de API (`src/Samba4Hub.Api`): Invocação do bootstrap seguro em Development e validadores com FluentValidation.
  - Orquestrador (`src/Samba4Hub.AppHost`): Provisionamento do container PostgreSQL com volume persistente e política de prontidão (`WaitFor`).
- **Fora de Escopo**: Endpoints de negócio CRUD, autenticação JWT/OAuth, gateway de pagamento e serviços de streaming (fases posteriores).

## 2. Definitions

| Termo | Definição |
|---|---|
| **Identity BY DEFAULT** | Estratégia de geração sequencial de chave primária no PostgreSQL (`GENERATED BY DEFAULT AS IDENTITY`), permitindo chaves autoincrementais ou inserções manuais para seeds. |
| **DocumentoFiscal** | Value Object imutável responsável pela sanitização e validação de dígitos verificadores de CPF (11 dígitos) e CNPJ (14 caracteres, incluindo padrão alfanumérico). |
| **AuditableEntityInterceptor** | Interceptor EF Core que atribui automaticamente `DataCriacao` e `DataAtualizacao` em UTC via `TimeProvider.System`. |
| **DesignTimeDbContextFactory** | Classe implementando `IDesignTimeDbContextFactory<Samba4HubDbContext>` que provê configuração isolada para a CLI `dotnet-ef` sem requerer o AppHost ativo. |
| **Seed de Instrumentos** | Carga inicial da taxonomia musical de samba e pagode realizada de forma determinística via `HasData`. |
| **Mural de Vagas** | Consulta principal da plataforma que busca vagas por status, cidade e data do evento. |

## 3. Requirements, Constraints & Guidelines

### Requisitos Funcionais e Estruturais
- **REQ-001 (Chaves Primárias)**: Todas as entidades de negócio DEVEM utilizar chave primária numérica `long` (`bigint` no PostgreSQL) mapeada com `UseIdentityByDefaultColumn()`. É expressamente PROIBIDO o uso de GUID/UUID como chave primária.
- **REQ-002 (Tabelas Associativas)**: As tabelas associativas puras `musico_instrumento` e `vaga_instrumento` DEVEM utilizar chave primária composta constituída pelas duas chaves estrangeiras (`long`).
- **REQ-003 (Documentos Fiscais)**:
  - `usuario.cpf_cnpj`: Obrigatório, com índice único (`ux_usuario_cpf_cnpj`), armazenando 11 dígitos numéricos (CPF) ou 14 posições (CNPJ numérico ou alfanumérico).
  - `perfil_contratante.cnpj`: Opcional (`string?`), armazenando 14 posições quando preenchido para contratantes PJ.
- **REQ-004 (Enums como Inteiros)**: Todos os enums de domínio DEVEM ser persistidos no PostgreSQL como colunas do tipo primitivo `integer` (4 bytes).
- **REQ-005 (Validação na Borda)**: A integridade dos dados enviados na API DEVE ser garantida via validadores com **FluentValidation**, rejeitando valores fora do intervalo dos enums ou regras monetárias com status HTTP 400.
- **REQ-006 (Precisão Monetária)**: Todos os campos financeiros (`cache_oferecido`, `valor_proposta`, `cache_minimo`, `cache_grupo_minimo`) DEVEM ser configurados com precisão `HasPrecision(10, 2)`.
- **REQ-007 (UTC Mandatório)**: Toda data/hora registrada com fuso horário (`DateTimeOffset`) DEVE ser gerada e persistida estritamente em UTC (`+00:00`), evitando falhas do Npgsql no tipo `timestamptz`.

### Restrições
- **CON-001**: O ciclo de inicialização de migrações (`MigrateAsync()`) DEVE executar exclusivamente quando o ambiente for `Development` e a string de conexão estiver definida.
- **CON-002**: O `Program.cs` da API NUNCA deve referenciar a camada `Samba4Hub.Data` diretamente; a injeção deve ser realizada através do método de extensão em `Samba4Hub.IoC`.
- **CON-003**: Nenhuma coluna do tipo `text` irrestrito é permitida; todos os campos de texto devem definir limite com `HasMaxLength()`.

### Diretrizes de Integridade
- **GUD-001 (Deleção em Cascata)**: `DeleteBehavior.Restrict` em todos os relacionamentos principais entre contas, perfis, vagas e candidaturas. `DeleteBehavior.Cascade` é restrito às tabelas associativas puras.
- **GUD-002 (Convenção de Nomenclatura)**: Nomes de tabelas, colunas, chaves primárias (`pk_`), chaves estrangeiras (`fk_`), índices (`ix_` / `ux_`) e constraints DEVEM seguir estritamente o padrão `snake_case`.

## 4. Interfaces & Data Contracts

### 4.1 Entidades de Domínio (`src/Samba4Hub.Domain/Entities/`)

## 5. Acceptance Criteria

- **AC-001**: Given a inicialização da API em ambiente `Development`, When `ApplyDatabaseMigrationsAsync()` for executado com conexão válida, Then o schema completo com 9 tabelas operacionais e a carga de instrumentos é criado sem erros.
- **AC-002**: Given a inicialização da API em ambiente de `Staging` ou `Production`, When `ApplyDatabaseMigrationsAsync()` for chamado, Then a migração é ignorada com registro de log informativo sem impacto no ciclo de subida.
- **AC-003**: Given uma tentativa de persistência com `Guid` como PK, When o modelo for validado, Then o compilador ou teste de arquitetura rejeita a definição.
- **AC-004**: Given um músico cadastrando instrumentos, When ele tentar marcar dois instrumentos como principais, Then o banco de dados rejeita a operação com violação do índice único parcial `ux_musico_instrumento_principal`.
- **AC-005**: Given um payload com CPF ou CNPJ alfanumérico válido (`12ABC34501DE35`), When validado pelo `DocumentoFiscal`, Then a validação é aprovada com sucesso.
- **AC-006**: Given um payload com CPF de dígitos repetidos (`11111111111`) ou enum inválido (`Status = 99`), When recebido pela API, Then o FluentValidation rejeita com HTTP 400.

## 6. Test Automation Strategy

- **Testes Unitários de Domínio (`test/Samba4Hub.Domain.Tests`)**:
  - `DocumentoFiscalTests`: Validação exaustiva de CPFs (válidos, inválidos, máscaras, repetidos) e CNPJs tradicionais e alfanuméricos gerados deterministicamente e via Bogus.
- **Testes Unitários de Persistência (`test/Samba4Hub.Data.Tests`)**:
  - `ModelMetadataTests`: Inspeção do `IModel` do EF Core garantindo que todas as PKs são `long`, nenhuma entidade usa `Guid`, todas as tabelas e colunas usam snake_case e decimais usam precisão `(10,2)`.
  - `MigrationExtensionsTests`: Validação com `NSubstitute` de que migrações são ignoradas fora de `Development`.
- **Testes de Integração com Banco Real**:
  - Uso do `Testcontainers.PostgreSql 4.16.0` para aplicar as migrações em um PostgreSQL real descartável e validar unicidade de CPF, índice parcial e constraints financeiras.

## 7. Rationale & Context

- **Opção por Bigint Identity vs UUID**: `bigint` consome 8 bytes contra 16 bytes de UUIDv4, melhora a localidade de cache em índices B-Tree e evita a fragmentação de páginas do PostgreSQL gerada por chaves aleatórias.
- **Enums Diretos como Inteiros**: A decisão de não criar tabelas de lookup adicionais elimina 9 tabelas e dezenas de `JOIN`s desnecessários nas consultas de mural e listagens, mantendo a simplicidade e a agilidade indispensáveis para a Fase 1 do MVP.
- **Validação com FluentValidation**: Centralizar a validação dos valores permitidos na camada de API garante mensagens amigáveis e estruturadas ao cliente antes que requisições inválidas atinjam o banco.

## 9. Examples & Edge Cases

### Cálculo do CNPJ Alfanumérico
Para um CNPJ como `12ABC34501DE35`:
- Caracteres 'A' a 'Z' são convertidos via fórmula `ASCII - 48` ('A' = 17, 'B' = 18, etc.).
- Multiplica-se pelos pesos regressivos com módulo 11 tradicional.
- Restos menores que 2 resultam em '0'; outros resultam em `11 - resto`.

### Vagas cruzando a meia-noite
Uma roda de samba pode ter `HoraInicio = 22:00` e `HoraFim = 02:00`. Não é aplicada constraint de validação `hora_fim > hora_inicio`.
